# Call sheet: Project 2: Internal Inventory Pull Request Portal

Worded so each answer is a fact or a yes/no. Question 7 is the only real tradeoff.

## Portal: inventory setup

1. Is inventory in ONE Shopify location or several (warehouse / store / showroom)?
   If several: which location do internal pulls physically come from?

## Portal: the request

2. Who may submit pull requests: everyone, or a specific list?
3. Besides item, size, quantity, reason, and expected return date, what else does
   Lillian need to see to decide (stylist/celebrity name, shoot date, destination)?
4. Are the reasons exactly: stylist/celebrity loan, design reference, photoshoot?
   Any others?

## Portal: approval

5. Is Lillian the only approver, and who approves when she is away?
6. How does she want to approve: one email per request, or a daily summary? Is
   clicking into Airtable to approve OK, or does she want to approve from the email?

## Portal: what approval does

7. Approved units immediately stop being sellable on the website. Is that what we
    want, even if a big shoot pull temporarily zeroes out a size online?
8. If a request exceeds available units: block the form, or allow and let Lillian decide?
9. Overdue reminders go to: requester only, or requester + Lillian? How often?
10. When pulled items never come back (gifted, damaged on set): what should the system
    do — write off, mark damaged, something else?

## Portal: switchover

11. Are open draft orders holding units today? Clean them up at launch? Does the portal
    replace draft orders on day one, or run alongside for a couple of weeks?
12. Same person who set up the Shopify app last time can create the portal's own app,
    correct? (Separate app keeps the CS agent at zero write access; same two-minute
    Dev Dashboard flow as before.)
